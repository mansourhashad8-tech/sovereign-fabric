# Sovereign Fabric

A self-evolving cognitive-executive system built around one rule: **it may
retry anything, but it may not claim anything it cannot show.**

It consults external sources, absorbs what it learns into a single fabric of
knowledge and executable capabilities, plans with classical search, extends
itself only through a verification gate, and runs every result through a
holistic validator that refuses overclaims.

This README is deliberately blunt about limits. A system that exaggerates its
own powers is not sovereign; it is a liability.

**Public repository**: [mansourhashad8-tech/sovereign-fabric](https://github.com/mansourhashad8-tech/sovereign-fabric).
The CI workflow runs the tests and the strict openness/vulnerability audit on
every push.

## Start here

- **Dashboard**: `/dashboard` — one self-contained page (no build, no CDN) that
  runs the full report on load and shows the verdict, plan, six scores, source
  status, capabilities, and limits.
- **Full report**: `GET /report` (JSON), `GET /report.md` (Markdown).
- **Self-assessment**: `GET /self`, or `python -m sovereign self`.
- **Claim check**: `POST /verify_claim` with `{"claim": "..."}`.
- **Openness audit**: `python -m sovereign audit --strict`; report at
  `SECURITY_DISCLOSURE.md`.
- **Local**: `python -m sovereign report --markdown` and
  `python -m sovereign serve --port 12000`.

## What this is

- **An external-guardianship layer** over 22 real public sources: arXiv,
  OpenAlex, Semantic Scholar, Crossref, DataCite, PubMed, Open Library,
  Wikidata, World Bank, GitLab, Wiktionary, Nominatim, DOAJ, GitHub,
  Hacker News, Hugging Face, PyPI, npm, Wikipedia, Stack Overflow, Zenodo,
  plus an offline engineering corpus. Each result carries provenance (source, URL, retrieval time,
  licence, confidence).
- **A unified fabric**: one SQLite store holds knowledge units, a concept
  graph, the capability registry, an append-only event log, a source cache and
  a failure memo. Knowledge retrieval and execution planning read the same
  store.
- **Instant absorption**: consulting, indexing (deterministic embeddings) and
  graph-linking happen in one pass, so a consulted fact is immediately
  searchable and traversable.
- **A capability registry** with versioning, hot-swap, quarantine and rollback.
- **Autonomous acquisition**: when planning is blocked, the system looks for a
  blueprint whose inputs are already reachable and whose outputs add something
  new, synthesises it through the gate, and re-plans. The bounded library has
  **24 blueprints** across text, Arabic normalization, lists, numbers, JSON and
  hashing; bridge blueprints let it go from text to lists or JSON and then to a
  second capability. It can chain several acquisitions into a multi-step bridge.
- **A bounded repair loop**: a cycle that fails a criterion retries with a
  broader query, keeps the best attempt, records every attempt, and returns an
  actionable diagnosis.
- **Recruited experts**: any OpenAI-compatible model can be asked for candidate
  implementations; every candidate still has to pass the local gate.
- **Self-directed practice**: the system forms small tasks from its own absorbed
  knowledge and attempts them, recording what worked.
- **A guardrail that attacks itself**: a red-team corpus measures the overclaim
  detector's blind spots, and the patterns are widened from what it finds.
- **A self-model derived from evidence**: it plans each goal it claims, counts
  what it owns, states what it cannot do, and audits its own verdict.
- **Lexical claim support**: a claim is checked against absorbed units; the
  result says `entails: false`, because vocabulary overlap is not entailment.
- **Randomized property checks**: invariants over the native chain catch a
  broken implementation that example tests might miss.
- **A cited brief for any topic**: consult, absorb, rank, and quote with
  provenance in English or Arabic headings. It is extractive, not synthetic.
- **Mastery practice**: the weakest goal is chosen from recorded cycles and
  practised with auto-extension, so a missing capability can be acquired.
- **Openness and mandatory disclosure**: MIT licence, a static scanner, a
  resolved licence inventory, an OSV vulnerability check, and a public
  disclosure report generated by the project itself.
- **Self-extension through a gate**: the system generates a capability from a
  behavioural spec and admits it only if it reproduces every example inside a
  separate interpreter with a timeout and a sanitized environment. Failures are
  quarantined, never silently kept.
- **Classical best-first planning** over capability types, with parallel
  multi-goal search and a failure memo that prunes proven dead ends — keyed to
  the operator set, so registering a new capability correctly re-opens search.
- **A holistic validator** scoring six criteria and rejecting absolute or
  unfalsifiable language (negation-aware).

## Recruiting other minds (external experts)

The system does not have to be the only model in the loop. `sovereign/expert.py`
speaks the OpenAI chat-completions protocol, so Groq, OpenAI, or a local server
can act as an expert. `sovereign/acquire.py` asks every configured expert for
candidate implementations, verifies each against the examples, and — if all
fail — feeds the failures back and asks again.

Nothing an expert says is trusted. Its output is a *candidate*; the same
subprocess gate that checks generated code checks it. If no expert is
reachable, acquisition says so and returns no capability.

```bash
export GROQ_API_KEY=...        # and/or OPENAI_API_KEY / OPENAI_BASE_URL
```

In this workspace the Groq key is present but the provider returns `401`, so
the live attempt records the error and admits nothing. The pipeline is
exercised end-to-end with injected experts in the tests.

## Finding a program, not just a template

`sovereign/programs.py` adds enumerative program synthesis. It searches a
whitelisted expression language (string and number transforms, up to depth two),
evaluates candidates in-process against the examples as a cheap filter, and
sends the first fit through the isolated gate. Admitted capabilities record
`source: "enumerative"` and the winning program label.

Live, with no model key:

- `Hello World -> hello-world` found `slug`
- `hello world -> Hello World` found `title case`
- `one two -> two one` found `words reversed`
- `[1, 2, 3] -> 6` found `sum`

This is not general synthesis: the examples are the whole specification, so a
program that fits them can still be wrong on unseen inputs. The gate makes the
claim precise — "reproduces these examples" — and the examples remain the
evidence.

## Measuring itself and keeping the faster implementation

`sovereign/optimizer.py` compares equivalent implementations of a capability.
A candidate must produce byte-identical output on a corpus before it is timed;
timing is the second gate. If nothing beats the current implementation by 5%,
nothing changes. A win is registered as a new capability version and can be
rolled back like any other.

Live, measured on this machine:

- `counts.summarize`: sorted list → `heapq.nsmallest` = **4.4x**
  (95% bootstrap CI 4.2–4.6x)
- `tokens.count`: dict loop → `collections.Counter` = **1.44–1.54x**
- `text.tokenize`, `report.format`, `text.summarize`: no verified gain, so
  they were left alone

```bash
curl -X POST 'localhost:12000/optimize?name=counts.summarize'
python -m sovereign optimize --all
```

## A bounded continuous loop

`sovereign/loop.py` runs a repeating tick: consult one topic, absorb what it
finds, optionally run one measured optimization, record the generation, sleep.
It starts and stops on command, keeps a short history, and records errors. It
is a scheduler with a stop button, not autonomy and not curiosity.

```bash
python -m sovereign loop --ticks 3 --sources local
```

Live first tick: 21 units absorbed, `tokens.count` optimized to `Counter` at
1.48x.

### Arabic normalization

Arabic text is normalized before tokenization: diacritics and tatweel are
removed, `أ/إ/آ` unify to `ا`, `ى` to `ي`, `ة` to `ه`, and Arabic punctuation
is dropped from tokens. English behaviour is unchanged. The same normalization
is used by `text.tokenize`, its optimized variant, the extractive summary, and
now the embedding tokenizer. Before that change the embedding regex accepted
only `[a-z0-9]`, so Arabic queries produced an all-zero vector and could not
retrieve Arabic knowledge at all.

Document vectors stay exact. A query mixes its exact vector with a light-stem
variant, so `الكتابات` can reach `كتاب` without re-embedding the store. This is
query expansion, not a neural model; the stemmer is a short prefix/suffix
list.

```python
from sovereign.arabic import tokenize_text
tokenize_text("الذكاءُ الاصطناعي، والتعلّم!")  # ['الذكاء', 'الاصطناعي', 'والتعلم']
```

A Bell state is real gate arithmetic, not a metaphor:

```bash
curl -s -X POST localhost:12000/invoke \
  -H 'Content-Type: application/json' \
  -d '{"capability":"quantum.simulate","payload":{"qubits":2,"gates":[{"gate":"h","target":0},{"gate":"cx","control":0,"target":1}]}}'
# probabilities [0.5, 0.0, 0.0, 0.5], unit_norm 1.0
```

The simulator is exact and bounded: 8 qubits (256 amplitudes), 64 gates, and
no hardware or speedup claim. Grover is bounded to 6 qubits and 10 iterations;
it demonstrates amplitude amplification, not a practical advantage.

`image.info` and `audio.wav_info` read headers from base64, bounded at 2 MB.
They report dimensions, channels, sample rate, bits, and duration; they do not
decode pixels, run OCR, or transcribe audio.

Compose them without writing a new module:

```bash
curl -s -X POST localhost:12000/pipeline \
  -H 'Content-Type: application/json' \
  -d '{"steps":[{"capability":"csv.parse","payload":{"value":"name,score\nb,2\na,1"}},{"capability":"table.aggregate","payload":{"column":"score","op":"sum"}}]}'
# {"ok":true,"value":{"column":"score","op":"sum","result":3.0},...}
```

The previous step's `value` is passed to the next step; a failure returns the
partial trace with `failed_at` and an error, not a fabricated result. Batch
calls use the same bounded envelope:

```bash
curl -s -X POST localhost:12000/invoke/batch \
  -H 'Content-Type: application/json' \
  -d '{"calls":[{"capability":"math.eval","payload":{"value":"2+3"}},{"capability":"text.redact","payload":{"value":"a@b.com"}}]}'
# {"ok":true,"results":[...],"elapsed_s":...}
```

## Learning from outcomes

`POST /feedback` records `-1`, `0`, or `1` for a capability, optionally with a
note and request ID. `GET /feedback/summary` returns counts and a smoothed score
`(positive - negative) / (count + 5)`. `GET /capabilities/search` adds
`0.05 * score` to each hit. The planner also uses the score as a bounded cost
multiplier, `1 - 0.25 * score` clamped to `[0.5, 1.5]`, so a route with
positive outcomes is preferred over an otherwise equivalent route. A successful
execution records `+1` for each executed step; a failed execution records `-1`
for the failed step. Automatic events are marked `auto:...` and remain visible
in the event log. This self-generated signal can reinforce a route that executes
correctly but is not useful; it is a preference signal, not external truth.

```bash
curl -s -X POST localhost:12000/feedback \
  -H 'Content-Type: application/json' \
  -d '{"capability":"math.eval","rating":1,"note":"answered correctly"}'
curl -s localhost:12000/feedback/summary
```

This is a bounded online preference signal, not gradient training. One rating
is smoothed by a prior of five, and the score is visible in every search hit.

## Runtime settings that cannot lower the bar

`GET /settings` exposes five allowlisted parameters: the planner feedback scale,
the planner cost floor and ceiling, the feedback prior, and whether automatic
outcome feedback is enabled. Every value has a hard range. Validation
thresholds, security invariants, and capability admission rules are not in the
allowlist, so a settings call cannot lower the system's own standards.

```bash
curl -s localhost:12000/settings
curl -s -X POST localhost:12000/settings \
  -H 'Content-Type: application/json' \
  -d '{"key":"planner.feedback_scale","value":0.3,"reason":"measured tune"}'
curl -s -X POST localhost:12000/settings/reset \
  -H 'Content-Type: application/json' -d '{"key":"planner.feedback_scale"}'
curl -s localhost:12000/settings/history
```

Every change is recorded with the old value, new value, and reason. `POST
/settings/tune` is a bounded heuristic: with at least 20 cycles, it raises the
feedback scale when the self-model's prequential skill is above 0.1 and lowers
it when skill is below zero. It reports its inputs and never claims that the
change is an improvement.

## External expert consultation

`POST /expert/ask` asks a configured OpenAI-compatible expert (Groq or OpenAI)
for text. Configure it with `GROQ_API_KEY` or `OPENAI_API_KEY`; `GET /experts`
lists what is available. The response is marked `verified: false` and is never
executed, parsed as code, or treated as an action. The request contains only
your question and optional system text; the fabric does not attach the store,
knowledge units, or environment. If the provider rejects the key or is down,
the endpoint returns `502` with the failure names; it does not fabricate an
answer.

```bash
curl -s -X POST localhost:12000/expert/ask \
  -H 'Content-Type: application/json' \
  -d '{"question":"Compare A* and BFS in two sentences."}'
```

`POST /self/repair` is the self-healing path. It imports every active built-in
entry, quarantines any entry that is missing or not callable, and re-admits a
known native or extra name at the next version. An unknown broken name stays
quarantined. It never invents a replacement and it records a `self_repair`
event with every action.

Or route an Arabic request into the planner:

```bash
curl -s -X POST localhost:12000/ask   -H 'Content-Type: application/json'   -d '{"request":"كلمات مفتاحية: الذكاء الاصطناعي الاصطناعي","sources":["local"]}'
# plan ["text.keywords"] -> [{"term":"الاصطناعي","count":2}, ...]
```

What these are, precisely: `text.langdetect` detects the dominant script, not
the language; `text.entities` is regex extraction, not NER; `text.similarity`
is Jaccard over tokens, not embeddings; `text.arabic_stem` is a light prefix /
suffix stripper, not morphology; `math.eval` is arithmetic, not algebra;
`math.stats` reports population standard deviation; `csv.parse` is bounded to
1000 rows and 50 columns; `html.text` strips tags and scripts but does not render
or execute a page; `toml.parse` and `ini.parse` return JSON strings;
`markdown.headings` recognises ATX headings only. Every bound is a conscious
limit, not a hidden one.

## Immunity, collective lessons, and the autonomy gate

`/immunity/status` is an online statistical detector, not deep learning. It
keeps a moving latency baseline and per-client error/path-diversity statistics,
adds fixed signatures for common scan paths, and quarantines a client for 60
seconds when the score crosses 3.0. Confirmed scan paths are kept only as
in-memory SHA-256 hashes (bounded at 1,000) and raise the score on repetition.
Client identifiers are hashed before they enter the event log; queries and
payloads are not logged.

```bash
curl -s localhost:12000/immunity/status
curl -s localhost:12000/immunity/incidents
curl -s -X POST localhost:12000/immunity/scan
```

`POST /immunity/scan` returns an analysis with a recommendation and
`automatic_code_patch: false`; it does not modify the OS or application code.

`GET /collective/export` emits anonymized lessons with no client identifiers,
IPs, queries, payloads, prompts, knowledge text, keys, or timestamps.
`POST /collective/import` accepts only the strict lesson schema and rejects
unknown fields, bad fingerprints, and raw data. This is a manual JSON exchange,
not federated learning, not a global brain, and it shares no model weights.

`GET /autonomy` is an operational gate with four checks: local capability
autonomy, loop continuity, safety evidence, and at least one collective lesson.
It returns `passed: false` and names the failed checks; it is not proof of life
or consciousness. `GET /evolution/reward` is a transparent event ledger, not
reinforcement learning.

## Deterministic execution protocol

`POST /protocol/execute` starts from the requested result, not from a capability
inventory. It runs a fixed escalation sequence of up to five routes:

1. `direct`: the current capability graph with one retrieval pass.
2. `broader_retrieval`: the same graph with a broader recent-survey query.
3. `all_sources_retry`: every configured source, when the caller restricted sources.
4. `autonomous_extension`: acquire or synthesize a missing blueprint, then re-plan.
5. `supplied_synthesis`: verified synthesis from a caller-supplied specification.

It stops at the first route where execution succeeds and all six validator
criteria pass. The response is `verified` only then. Otherwise it returns
`escalation_required`, the exact failed criteria, the best route, and concrete
`next_actions`; it does not return a candidate value as if it were verified.

```bash
curl -s -X POST localhost:12000/protocol/execute \
  -H 'content-type: application/json' \
  -d '{"request":"planning search text","text":"a b a","sources":["local"],"budget_s":1,"max_alternatives":2}'

curl -s localhost:12000/protocol
curl -s -X POST localhost:12000/protocol/language \
  -H 'content-type: application/json' -d '{"text":"..."}'
```

`POST /protocol/language` audits text against the five Arabic prohibited
expressions and their English equivalents, and returns `compliant` plus exact
positions. Every protocol message is passed through this audit, and the
response includes the result.

Limits: `verified` means the six-criterion validator passed; it is not a
semantic proof of intent. The route search is bounded at five routes. Open-ended
goals still require relevant sources or a synthesis specification. Freshness
is scored inside a 180-day window; older knowledge is not counted as recent.

## Capability-demand ledger

Every `escalation_required` response is also a measured gap. `GET /gaps` groups
runs by goal type, counts failed criteria, and proposes bounded capability names
with `status: "demand"` and `auto_created: false`. `GET /protocol/history`
returns the append-only run and gap events. Neither endpoint stores the raw
request: only a 16-hex-character SHA-256 prefix is recorded.

```bash
curl -s localhost:12000/gaps
curl -s localhost:12000/protocol/history
```

The ledger is a design queue, not automatic self-modification. A recurring gap
is evidence for the next capability; it is not a capability by itself.

## Hybrid retrieval

`GET /knowledge/search` now accepts `mode=vector`, `mode=bm25`,
`mode=semantic`, or `mode=hybrid` (default). Vector retrieval is the original
deterministic embedding plus authority and recency. BM25 preserves rare exact
terms. Semantic retrieval learns PPMI co-occurrence vectors from the current
corpus with deterministic random indexing; it is distributional, not neural.
Hybrid uses reciprocal rank fusion (RRF, k=60) over vector and BM25. The hybrid
score is an RRF score, not a probability, and the API returns the mode used.

`POST /ranking/evaluate` computes nDCG@k and MRR from an explicit ranked id list
and relevance map. It reports the metric only. `GET /ranking/benchmark` runs
the same 12 queries over the offline local corpus in vector, BM25, semantic,
and hybrid modes; it is a reproducible regression check, not a public leaderboard. The
BM25 token statistics are cached and invalidated on every knowledge write;
`GET /cache/stats` reports the index revision, document count, and cache state.
On the 2026-11-24 run at k=5, vector and hybrid scored nDCG 0.883201 and
MRR 1.0; BM25 and semantic scored nDCG 0.874322 and MRR 1.0. Neither hybrid nor
semantic beat vector on this small set, so the system does not claim that they do.

## Decision memory

Every protocol run writes one `decision.record` event with the chosen route,
scores, alternatives, next actions, and a rationale. It stores a 16-hex request
hash, never the raw request. `GET /decisions` shows aggregates and exact-hash
reuse candidates; `GET /decisions/{request_hash}` returns that request's
decisions. `automatic_reuse=false`: the memory is for audit, not silent replay.

## A self-model that plans its own claims

`GET /self` does not describe itself from a script. It asks the planner whether
each claimed goal is reachable, counts active capabilities, absorbed units,
recorded cycles, and optimizations, runs the property checks, then writes a
verdict and passes that verdict through the overclaim detector.

Live shape:

```text
Precise self-assessment: 129 active capabilities (129 builtin, 0 synthesized),
N absorbed knowledge units, and 22 external sources. X of Y recorded cycles
passed every criterion. Property checks: 40/40 passed. 17 limits are declared (18 without an expert).
I am not conscious, not quantum, and not a million-fold accelerator.
```

`python -m sovereign self` prints the same assessment with its evidence.

`GET /self/calibration` scores the self-model's own predictions. For each
recorded cycle it predicts success from the goal's prior outcomes, then scores
that prediction before adding the cycle's result. It reports the Brier score,
the 0.25 baseline, a skill score, and the last rows. Small samples make this a
diagnostic, not a guarantee; a negative skill score is shown as negative.

## Sovereign orchestration of external media

`GET /orchestration/providers?probe=true` probes real providers and reports one
of `ready`, `configured`, `blocked_credits`, `expired_credential`,
`unauthorized`, `workflow_missing`, or `unreachable`. Nothing is marked ready
from a credential name alone.

| Provider | Capability | Heavy | Honest role |
|---|---|---:|---|
| GitHub Actions | `compute.python`, `compute.pytest`, `compute.audit` | yes | bounded `workflow_dispatch` runner |
| Hugging Face Hub | `hub.metadata`, `hub.models` | no | model metadata |
| Hugging Face Inference | `inference.chat` | no | external inference, credit-gated |
| Groq | `inference.chat` | no | external inference, key-gated |
| Local control | `control.plan`, `control.qa` | no | planning and quality only |

`POST /orchestration/plan` builds a dependency-ordered assignment. A heavy task
is blocked if no external provider is ready; the local interpreter is never
substituted. `POST /orchestration/run` executes bounded tasks, applies a
declared quality standard, and reassigns a failed task once. `POST
/orchestration/provision` can provision an ephemeral GitHub Actions run inside
the existing account; it cannot create a new account, because provider signup
needs a human, payment, or CAPTCHA.

Live evidence on 2026-11-25: GitHub Actions accepted a `workflow_dispatch`
and completed `tests` (run 45720153329) and `audit` (run 45720322520) with
success; the orchestrator observed both. Hugging Face Hub answered `whoami`;
Hugging Face Inference returned `402 blocked_credits`; Groq returned `401
expired_credential`. No account was created.

The quality gate implements `schema`, `reproducibility`, `ACID`,
`ISO_25010_subset`, and `ZKP`. ISO and ACID are subset checks, not
certifications. The ZKP gate requires a proof, public signals, and a passing
cryptographic verifier result; a structurally plausible artifact does not pass.

## Evidence, not entailment

`POST /verify_claim` retrieves units and measures how much of the claim's
content vocabulary they contain. It returns `supported`, `score`, the
supporting units, and `entails: false`. An unrelated claim is refused.

```bash
curl -s -X POST localhost:12000/verify_claim   -H 'Content-Type: application/json'   -d '{"claim":"retrieval augmented generation improves factuality"}'
```

This is lexical and distributional support over the current fabric. It is not a neural
entailment engine, and it does not pretend to be one.

## Property checks

`GET /properties` generates random payloads and asserts invariants: the sum of
counts equals the token count, `top` is the correctly ordered first five,
formatted lines match the report, and a summary is a substring of its input.
A deliberately broken implementation is caught; the tests prove it.

## Confidence intervals

The optimizer reports a 95% bootstrap confidence interval for every speedup.
A point estimate without an interval is a weaker claim than it looks.

## A cited brief for any topic

`POST /brief` accepts any query, consults the 22 sources, absorbs the result,
ranks the units, and returns an extractive Markdown brief with provenance. It

## Intent learning

`GET /intent/classify` runs a small multinomial Naive Bayes classifier over
word and character n-gram features. `GET /intent/model` reports its label,
document, feature and update counts; `POST /intent/learn` adds one labelled
example at runtime. The deterministic keyword router still runs first. The
model is only a fallback when no keyword matches, confidence is at least 0.80,
and the margin over the runner-up is at least 0.40; otherwise the request stays
a markdown default. The seed set has 66 examples over 22 labels. On a
hand-written 10-example held-out check it scored 9/10 (0.90). That is a small
internal check, not a public benchmark. Updates are bounded at 5,000 and are
session-local: the model is not retrained from the event log on restart.

## Hyper kernel

`sovereign/hyper.py` adds four in-process mechanisms:

- **Holographic memory**: keys and values are bound with circular convolution
  and superposed into one vector. Recall unbinds the query and ranks stored
  values. It is a classical HRR, not quantum hardware and not a quantum
  speedup.
- **State bus**: components publish and read Python object references in the
  same process. There is no serialization and no HTTP/gRPC hop on this path.
- **Inner observer**: a bounded ring buffer records component latency and
  errors, flags outliers, and can invoke a registered healer. Its overhead is
  measured, not zero.
- **Internal clock**: monotonic `perf_counter_ns` ticks, a measured resolution,
  and a threaded barrier that reports arrival skew. It does not claim
  picosecond precision.

One live run on this host with 50 benchmark iterations:

| Mechanism | Measured p50 |
|---|---:|
| Bus put + get | 2.60 µs |
| Memory remember + recall (50 items) | 1.76 ms |
| Observer observe | 2.89 µs |
| Clock tick | 0.93 µs |
| Clock resolution | 120 ns |

The memory is capped at 10,000 items and the bus at 2,000 keys. Recall is
O(items × dim) for the value comparison plus the FFT unbind; it is not
constant-time. A corrupted superposition can be rebuilt from the stored
bindings by the observer's healer. `/evolve` publishes its last cycle object on
the direct bus and records the cycle duration with the observer.
These are engineering bounds; they are not "millions at once", near-light
signalling, or picosecond synchronisation. The API reports those limits
explicitly.

Endpoints: `GET /hyper/status`, `GET /hyper/benchmark`,
`POST /hyper/memory/remember`, `POST /hyper/memory/recall`,
`GET /hyper/memory`.

## Attacking its own guardrail

`GET /redteam` pushes a corpus of absolute claims through the overclaim
detector and reports coverage. Red-teaming found a real bug: the `100%` pattern
had a trailing word-boundary that made it miss. Coverage is now 20/20 on the
corpus; that is evidence about the corpus, not proof of completeness.

## Many routes

When the first plan's execution fails, the engine asks the planner for
alternative routes (found by banning the last step of the previous plan) and
tries them before reporting failure.

## Execution: parallel, cached, speculative, remote-optional

`sovereign/execution.py` is a real batch engine, not a metaphor.

- **Parallelism**: serial, threads, and processes. `auto` uses processes for
  batches of 64 or more. The engine runs the same workload serially first and
  reports the measured ratio. On this 4-core box, 2000 CPU-heavy tasks took
  3.0s serially and 1.25s across four processes: **2.36x**. The same tokenize
  batch is *slower* in parallel (0.44x) because pickling costs more than the
  work, and the engine says so instead of hiding it.
- **Hot cache**: content-addressed in-process cache with TTL. Search results and
  embeddings are cached; measured hit latency is about **4 microseconds**. This
  is the only place where "sub-millisecond" is true.
- **Speculative prefetch**: when a request arrives, the engine predicts likely
  goals and warms embeddings for the request and its variants. A prediction is
  used only on an exact key match; otherwise it is discarded. `/evolve` warms,
  `/knowledge/search` verifies (see `prefetch_hit`).
- **Remote compute hook**: `RemoteExecutor` posts batches to
  `SOVEREIGN_REMOTE_EXECUTOR` when configured. With no endpoint it raises
  `RemoteUnavailable`, and `/remote/status` reports `available: false`. No HPC
  credentials exist here, so none is claimed.

```bash
python -m sovereign.cli bench --n 2000 --workload cpu --mode processes
```

## API hardening

The API has an optional key, a per-client rate limit, a body cap, and
restrictive headers. The key is opt-in:

```bash
export SOVEREIGN_API_KEY=change-me        # non-GET requests need X-API-Key
export SOVEREIGN_RATE_LIMIT=120           # requests per window
export SOVEREIGN_RATE_WINDOW=60
export SOVEREIGN_MAX_BODY=2000000
```

When the key is set, every POST/PUT/DELETE requires `X-API-Key`; the comparison
uses `hmac.compare_digest`. GET endpoints stay public for the dashboard and
report. Responses carry `X-Content-Type-Options`, `X-Frame-Options`,
`Referrer-Policy`, `Permissions-Policy`, `Cross-Origin-Opener-Policy`, a
self-only CSP, and `X-RateLimit-Remaining`.

`tests/test_dast.py` is an in-process dynamic suite: SQL-injection-shaped
input, malformed JSON, XSS-shaped input, oversized bodies, wrong methods, and
unknown routes. It checks status codes and response types, not just unit
functions. Guardian fetches are http(s)-only and capped at 2 MB
(`tests/test_fetch.py`).

## Openness and mandatory disclosure

The source is MIT-licensed. `python -m sovereign audit --strict` parses every
Python file under `sovereign/`, resolves direct and transitive requirements,
classifies their licences, and queries OSV for known vulnerabilities. It fails
closed: a high finding, an unknown licence, an OSV hit, or a missing licence
file exits non-zero.

Live audit on this tree:

- **0** findings from the static rules (critical, high, medium, low)
- **23** resolved dependencies, all with recognised open licences
- **0** OSV vulnerabilities for the resolved versions
- **69** source files hashed with SHA-256
- `LICENSE` present (MIT); `OPENNESS_MANIFEST.json` records the hashes
- **CycloneDX 1.5 SBOM** at `sbom.cdx.json` (`GET /security/sbom`)

The scanner found real issues and they were fixed, not hidden:

- `eval()` in the program search was replaced with a whitelisted AST evaluator.
- `exec()` in batch source execution was replaced with an isolated subprocess
  (`python -I -c`, sanitized environment, finite timeout).
- SHA-1 identifiers became SHA-256.
- The arXiv endpoint moved from `http://` to `https://`.

## What this is not

| Claim | Reality |
| --- | --- |
| "A living entity" | It is software. No consciousness, no autonomy beyond its loop. |
| "A deep-learning immune system" | The detector is online statistics and fixed scan signatures. It has no neural network and its state is in-process. |
| "Federated learning / a global brain" | Collective memory is a manual anonymized JSON exchange. There is no network transport, no model averaging, and no global peer. |
| "Self-healing every vulnerability" | Self-repair only quarantines broken built-in entries and restores known names; it cannot patch the OS or invent missing code. |
| "An absolute guarantee for any request" | The protocol runs up to five bounded routes. When none passes all six criteria it returns `escalation_required` with exact gaps and next actions, not a fabricated success. |
| "A million times faster" | No such speedup exists here. Speed is *measured* against a budget; unmeasured speed scores zero. |
| "Quantum pathfinding" | The planner is classical A*. A quantum *simulator* gives no speedup over the algorithm it simulates; only real quantum hardware might, and none is used. |
| "Never fails" | It retries, degrades gracefully and reports honestly. If it cannot meet a criterion, it says so and returns `ok: false`. |
| "General program synthesis" | Enumerative synthesis over a whitelisted expression language; it fits the examples you give it, not arbitrary intent. |
| "Continuous autonomy" | The loop is a bounded scheduler: consult, absorb, optimize, sleep. It has a stop button and no goals of its own. |
| "A million-fold self-improvement" | The optimizer keeps only measured wins on this machine: 4.4x and 1.5x on two functions, no gain on three others. |
| "Semantic entailment" | Claim checking is lexical support over absorbed text; it returns `entails: false` on purpose. |
| "A 2026 research snapshot" | No frozen snapshot exists. It consults live sources and reports retrieval dates; it cannot know what is not published. |
| "Self-awareness" | The self-model is computed from the registry, event log, and planner. It is evidence, not subjective experience. |
| "A synthesis engine" | The brief quotes and cites absorbed units. It does not infer, translate, or verify truth. |
| "A guaranteed learner" | Mastery practice records before/after rates; it can fail to improve, and the table says so. |
| "A general-purpose agent" | 129 bounded deterministic capabilities. The math is an AST evaluator, the entities are regex, the stemmer is rule-based, and the similarity is Jaccard. Breadth is not general reasoning. |
| "Zero vulnerabilities" | The audit reports 0 findings from these rules and 0 OSV hits; that is not a proof of absence. |
| "A security certification" | The scanner is public and conservative; it is not an external audit or a DAST suite. |
| "A closed model" | No closed-source library is required. The optional expert endpoint is a service, disabled by default. |
| "A full OS sandbox" | Synthesized code runs in a separate process with a sanitized environment and a timeout. It is not a kernel sandbox. |
| "A distributed rate limiter" | The limiter is in-process, per client. It does not coordinate across replicas. |
| "An Arabic translator" | The system normalizes Arabic and routes Arabic requests; it does not translate content. |
| "Sub-millisecond execution for any task" | Only cache hits are microseconds; real work takes real time. |
| "Quantum parallel processing" | A classical process pool on 4 cores; measured 2.36x on CPU-heavy work and slower on trivial work. |
| "Borrowed supercomputers" | A remote hook exists; no endpoint is configured, so it refuses. |

## The six pillars, mapped

| Pillar | Implementation | Honest limit |
| --- | --- | --- |
| 1. External guardianship | `sovereign/guardians/` — protocol, parallel registry, cache, rate limits, per-source status | A dead source degrades the result; it does not fail the run |
| 2. Unified cognitive/executive fabric | `store.py` — knowledge, graph, capabilities, events in one DB | Hashed and PPMI embeddings, not a neural model |
| 3. Accelerated self-engineering | `synthesis.py` + `programs.py` + `optimizer.py` + `capabilities.py` — enumerate, verify, benchmark, admit, roll back | Narrow expression language; the examples are the spec; only measured wins are kept |
| 4. Constraint transcendence | `pathfinder.py` — retry alternate routes, reframe goals, prune dead ends | Constraints are engineering problems, not magic |
| 5. Hyper-accelerated determinism | deterministic embeddings, deterministic search, memoised failures, retry loop, measured batch speedup, measured self-optimization | 2.36x on 4 cores for CPU-heavy work; 4.3x on one function; no universal acceleration |
| 6. Holistic validation | `validator.py` + `selfmodel.py` + `evidence.py` + `properties.py` — six scores, overclaim refusal, planned self-claims, lexical support, invariants | The validator and self-model can be wrong; evidence is lexical; properties are hand-written |

## Honesty model

1. **Provenance or it did not happen.** Every knowledge unit and capability
   carries its source.
2. **Evidence or it is a hypothesis.** `validate` fails a claim set with no
   evidence.
3. **Measured speed only.** Speed is `budget / measured_duration`; a missing
   measurement scores 0.
4. **Overclaims are refused.** "Million-fold", "quantum advantage",
   "guaranteed", "no failures", "impossible", "living entity", "AGI" fail the
   gate — unless negated ("we do not claim quantum advantage").
5. **Generated code is quarantined until it passes.** Verification runs in a
   subprocess with a timeout and a secret-stripped environment.
6. **Failures are remembered.** Proven dead ends are pruned on later runs,
   scoped to the operator set that produced them.
